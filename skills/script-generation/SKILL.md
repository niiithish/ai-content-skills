# Script Generation

Write scripts for short-form video that will be generated by AI, not filmed. The output is a cut list: numbered cuts, each with the spoken line and the shot that carries it, timed to the clip length limits of the video engine.

A script that reads well as a paragraph but cannot be cut into 3-second beats is a failed script. Write the edit, not the essay.

## Non-negotiables

These four kill more short-form ads than weak copy does.

1. **Pace.** Cuts are short. Default to 2-3 seconds per cut and never exceed 3 unless the user asks. A 30-second ad is 10 or more cuts. If a cut cannot justify its length, cut it in half or delete it.
2. **Environment changes.** Each cut moves somewhere new or shows something new happening. Repeating a location across an entire ad reads as slow no matter how good the copy is. Six cuts in one room will lose the viewer.
3. **No ambiguous pronouns.** When the script contrasts the product against something worse, every "these", "it", and "they" must have exactly one possible referent. See the anti-confusion rule below — this is the single most common serious defect.
4. **Zero ad voice.** No "introducing", no "game-changing", no "obsessed", no three-adjective stacks. Read every line aloud; if a person would not say it to a friend, rewrite it.

## Workflow

1. **Gather the product truth.** Read the product page if a URL is given. Pull the material spec, the actual differentiator, social proof, and guarantees. Note any place the source contradicts itself and avoid that claim rather than picking a side.
2. **Place the awareness stage.** This decides the whole script. See the awareness table below.
3. **Pick the angle**, then write the hook. Hook patterns: [references/hooks.md](references/hooks.md).
4. **Write the voiceover** as one continuous spoken take, then break it into cuts.
5. **Assign a shot to every cut**, with an environment for each.
6. **Audit** against [references/audit.md](references/audit.md). Do this before showing the user anything.
7. **Write the tracker** to a markdown file when the project spans more than a couple of clips. Format: [references/tracker.md](references/tracker.md).

## Awareness stage decides the script

Getting this wrong is why scripts feel generic. Diagnose before writing.

| Stage | What they already know | Script opens on |
|---|---|---|
| Unaware | no problem felt | a relatable moment that names the problem |
| Problem-aware | feels the pain, no idea solutions exist | agitate briefly, then reveal the category |
| Solution-aware | knows the category, has been burned by it | differentiate against the thing they already tried |
| Product-aware | knows this brand, has not bought | proof, objection handling, risk reversal |
| Most aware | ready | offer and urgency |

**Solution-aware is the most commonly misdiagnosed.** Someone who already owns three cheap versions of the product does not need the problem explained; agitating it insults them. Differentiate against their past failures instead. The pivot line is "here is why the one you tried failed and this one does not."

## The anti-confusion rule

When the script contrasts the product against inferior alternatives, the viewer hears the audio once with no rewind. Any pronoun that could point at the product will be heard as pointing at the product.

Broken:

> I used to buy these constantly. Cute for a week. Then your neck turns green.

"These" is unanchored, so the viewer hears the advertised necklace turning their neck green. The ad now argues against itself.

Fixed:

> Every gold chain I owned before this one died in about two weeks. Green neck, patchy plating, straight in the bin.

Three devices do the work: an explicit noun phrase ("every gold chain I owned"), a temporal boundary ("before this one"), and a terminal verdict ("straight in the bin") that puts the failures in the past. Apply all three whenever a script has a villain.

Reinforce it visually: the failed version must look physically different from the hero product on screen, not merely older. If the villain prop reads as the same object aged, the contrast collapses.

## Structure

Beat order for a 25-35 second ad. Adjust the counts to length, but keep the order.

```
Hook            cuts 1-2    a question or claim that earns 3 more seconds
Credibility     cut 3       the specific detail that proves real use
Villain         cuts 4-5    what they tried before, and how it failed
Mechanism       cut 6       why this one is built differently
Proof montage   cuts 7-9    the claim demonstrated, one environment per cut
Resolution      cut 10      the emotional payoff, understated
Handoff         cut 11      into the offer
```

**Hook.** The first two seconds decide everything. A question the viewer wants answered outperforms a claim. Borrowed curiosity — "someone asked me whether..." — outperforms self-promotion, because it frames the ad as an answer rather than a pitch.

**Mechanism.** Say why in plain physical terms: what it is made of, what that prevents. Skip spec-sheet numbers and skip any figure the source contradicts.

**Proof montage.** The fastest section. One environment per cut, no dialogue needed, purely visual escalation of the same claim.

**Handoff.** When the user is attaching their own offer clip, end mid-sentence on the setup line and let the attached clip complete the thought. Never speak price in the AI-generated portion.

## Voiceover, not on-camera dialogue

Default to voiceover over silent b-roll for AI-generated ads. Lip-sync on generated video is unreliable, and voice character drifts between separate generations. One continuous voiceover take, sliced across the cuts, stays consistent and lets any cut be regenerated without re-recording.

Write the voiceover as one block first so the rhythm is continuous, then map it to cuts. Line breaks are breath pauses. Include delivery notes: accent, age, energy, and stability if the user is using a synthesis tool.

## Numbers and claims

Concrete beats round. "Four months" is a real person; "months and months" is a copywriter. But keep durations inside what the user can defend — an inflated timeline is both a trust risk and an ad-policy risk.

Flag every claim the user must confirm before publishing, as an explicit checklist. Duration of use, specific locations, and results are the usual suspects. Never invent a review count, a rating, or a certification.

## Output format

Deliver three things, in this order:

1. **The voiceover**, as one continuous block with breath breaks and delivery notes.
2. **The cut list**, as a table: cut number, duration, the line spoken over it, the shot, and the environment.
3. **The claims checklist**, listing what needs verifying.

Group cuts into generations that respect the video engine's clip cap, and note which generations carry internal cuts. Then hand the cut list to **video-generation** for the actual prompts.

## Revision

When the user rejects a script, diagnose the category before rewriting, because the fix differs:

| Complaint | Actual cause | Fix |
|---|---|---|
| "boring", "people will sleep" | cuts too long, one location | halve every cut, change environment per cut |
| "reads like an ad" | marketing register, feature stacking | rewrite in speech, cut to one claim |
| "confusing" | ambiguous referent or unclear pivot | apply the anti-confusion rule |
| "too long" | too many beats | delete beats, never speed up delivery |
| "not my style" | wrong register | ask for one reference ad they like |

Rewrite from the beat structure rather than editing sentences. Patching individual lines keeps the defect that caused the rejection.
