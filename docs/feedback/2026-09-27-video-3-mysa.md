# Feedback: upwork-calvin/video-3 (Mysa "Dose-to-Done Timeline", photoreal ad)

These notes are from the Claude session that made the video (Sept 26–27 2026). The user wants the skills and workflow fixed, so the next session doesn't repeat these mistakes. The project is at `~/Work/upwork/upwork-calvin/video-3`.

## What the user does and doesn't want from us

- **The user edits the video themselves:** stitching clips and timing them to the VO. Our edits got about 90% there and weren't good enough, so don't offer to edit.
- **We do:**
  - plan;
  - stills and clips, where we run the 360p batches and review them ourselves;
  - the 1080p finals, which the user runs from a command we give them;
  - **captions**, burned into their finished edit.
- **Replies are terse (TL;DR).** Long write-ups got "man you talk too much".

## 1. The folder structure is a mess (the user's biggest complaint)

What video-3 looks like now:
- `clips/` holds about 185 flat files: clip mp4s, plus about 30 manifest `.json` files, 30 `.flow-batch.json` files and 19 `batch-*.log` files.
- `stills/` holds 220 flat files in the same state.
- There are no `scene-N/` folders and no `takes/` folders, just `clips-redo17.json` and the like beside the media.

The user said they had specified their preferred structure in the skills, yet neither `clips/` nor `stills/` follows it.

Root causes:
- **The photoreal path has no production skill.** The structure (`scenes/scene-N/…`, `takes/`, `make.py`, "don't write your own batch files") lives only in `animated-video-production`. `video-plan` hands photoreal work to `photoreal-still-prompt` plus the sheet skills, and those only write prompts. So the agent improvised with hand-written flow manifests, one per retry round, all dumped beside the media.
- **`flow batch` writes `<manifest>.flow-batch.json` next to the manifest**, and our `> batch-x.log` redirects landed in the same place.
- **review-board:** adopting it mid-project had some effect. It shows any media anywhere, so nothing pushed toward the folder layout, and the flat layout "worked" there.

Suggested fixes:
- Make the production scaffolding style-agnostic:
  - either pull `init-project.sh` + `make.py` out of `animated-video-production` into a shared skill;
  - or add a `photoreal-video-production` skill that `video-plan` hands photoreal work to.
- Use the same layout as animated: `scenes/scene-N[/scene-Na]/scene-Na-vN.jpg`, `takes/`, and `clips/clip-N/…`.
- Keep manifests, flow state and logs out of the media folders, e.g. in a hidden `.flow/` or `batches/` folder. Ideally the flow CLI writes its `.flow-batch.json` and logs there by default.
- Add a hard rule: never create ad-hoc manifest files per retry round; `make.py` (or its photoreal twin) owns batching.

## 2. Captions: about 7 rounds to land the style (make this a skill)

The user will keep asking us for captions only, so this should be a reusable skill with a locked default style.

The first engine was `caps.py`. A copy is at `docs/feedback/2026-09-27-caps.py`, and the live one is in `video-3/captions/caps.py`. It does:
- faster-whisper `small.en` word timestamps from the user's edit;
- a char-level difflib alignment to the script text, so wording and punctuation come from the script, not from whisper;
- per-sentence DP chunking into 2-line captions: about 36 chars, max 50, preferring comma breaks, no short orphans;
- PIL renders one transparent PNG per interval, driven by an ffmpeg concat list and an overlay;
- `-c:a copy`, so the audio is untouched.

What the user rejected, in order, and the final locked spec:

1. **Position.** Captions exactly at center: rejected. They belong at the **bottom edge of the Meta/TikTok caption safe box**. On 1080×1920 the box is x 40–1050, y 220–1500. The caption block's bottom goes at about y 1480, and top labels sit at about y 245.
2. **Section labels** (HOURS / DAYS 4–6 / WEEK 3…). A big white bold super with a shadow in the middle was "pretty bad". Then white boxes like the captions: rejected too. Final: the **same box shape, placed at the top, `#EA4040` background, white text**, on screen for 3 s from the line.
3. **Line joins.** Separate rounded rectangles per line leave a notch where lines meet: rejected. Final: **one merged shape**, with convex corners rounded and **concave fillets** at the step between lines of different widths. PIL does it by union mask plus per-corner patches, supersampled 4×.
4. **Vertical spacing (took 3 tries).** The first version had a big gap between lines and tight padding above and below. The second tightened line pitch and added outer padding, but anchoring on font ascent put visibly more space above the text. Final: vertical placement from **cap height**, with equal space from the cap top and from the baseline to the box edges in each line box. Line pitch is about 1.95× cap height (74 px at 54 px TikTok Sans SemiBold), and line boxes touch. This matches the TikTok reference the user liked.
5. **Other rules:**
   - at most 2 lines per caption, and nearly every caption is 2 full lines;
   - the font is TikTok Sans SemiBold, supplied by the user;
   - quotes are curly;
   - the text is `#111` on white.

Process lessons:
- **Show one preview frame first.** Composite a real frame of the edit with the caption and a label, send it, and render the full videos only after a yes. The user asked for exactly this after two full renders missed.
- **Render to a temp file, then `mv`.** The user stopped a render midway and it left a broken deliverable with no moov atom.
- **Keep the caption tool in the project** (`video-N/captions/`), never in the session scratchpad. The scratchpad was wiped between sessions and the script had to be rebuilt from the transcript.
- **Deliverable names:** `Mysa_Dose-to-Done_Hook1-Control_9x16.mp4` in `deliverables/`, following `<Brand>_<Concept>_<Variant>_<Ratio>`.

## 3. Clip and still problems the user hit (for prompt and review skills)

- **Real-life logic over "composition".**
  - A computer monitor angled away from the person got "in IRL don't we have the monitor straight?".
  - A single sheet of paper multiplied into several, and a new paper appeared from thin air.
  - Check props for object permanence when reviewing.
- **The subject never looks at the camera** unless the shot calls for it.
- **The softgel swallow is the hardest beat.** Failures:
  - the pill vanishes;
  - she takes a tiny sip and the water never drops;
  - the pill count is wrong (2 pills become 3).
  - Use timed 6 s beats and 2 seeds, and count objects in review.
- **Emotional tone must match the VO line.** Clip 9 showed a happy woman on a "problem" line.
- **Static shots read as boring.** The user wanted a subtle camera move or slow zoom like the reference. A slow zoom added in post (ffmpeg zoompan) was acceptable.
- **Casting age.** The couple read as too old for the intimacy beat, so they were recast as mid-aged. Check the cast against the scene's premise.
- **Intimacy vs Google's content filter.**
  - Night + pyjamas + bed always came back NOT_FOUND, even for mild prompts.
  - Evening + knitwear + armchair/sofa + laughing passed.
  - The target is "romantic but not too sexual".
- **Reuse is welcome.** The user prefers reusing already client-approved clips from earlier videos (`video-1/final/…`) over regenerating.
- **Look:** realism, no AI look. The user rejected a "red glow" stylization. For the anatomy/science shot, match the inspo's diagram look.
